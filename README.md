# LunaCycle

**LunaCycle** is an educational FemTech platform focused on menstrual health, reproductive health conditions, menstrual products, and health literacy.

The project was created to help close gaps in accessible health information by bringing together condition education, symptom awareness, menstrual tracking, and evidence-based information about menstrual products and their ingredients.

> **Important:** LunaCycle is an educational resource, not a medical diagnostic tool or substitute for professional medical care. Information provided by the platform should not be used to diagnose, treat, or rule out a medical condition.

---

## Features

### Symptom Checker

An educational symptom-matching tool that allows users to:

* Select relevant symptoms
* Provide additional information such as frequency, duration, timing, and severity
* Receive ranked condition matches
* View estimated symptom-match percentages
* See other conditions that may share similar symptoms
* Understand which reported symptoms contributed to each result
* Learn when additional information may be needed

The percentages shown by the checker are **informational estimates generated by the application's matching system**, not clinically validated probabilities or diagnoses.

The checker is designed to help users recognize patterns and identify topics they may want to discuss with a healthcare professional.

---

### Period Tracker

A menstrual cycle tracker designed to help users record and understand their periods over time.

Planned functionality includes:

* Period start and end dates
* Cycle length
* Flow information
* Symptoms
* Pain and other menstrual experiences
* Historical cycle data
* Editing and deleting recorded information
* Integration with information voluntarily entered into the Symptom Checker

Users should remain in control of what information is saved, changed, or removed.

---

### Condition Explorer

An educational library covering menstrual and reproductive health conditions and related conditions that may overlap with menstrual symptoms.

Potential topics include:

* Adenomyosis
* Endometriosis
* Fibroids
* Polyps
* PMOS (previously PCOS)
* Primary ovarian insufficiency
* Amenorrhea
* Dysmenorrhea
* Heavy menstrual bleeding
* Premenstrual syndrome
* PMDD
* Menstrual migraine
* Thyroid-related conditions
* Bleeding disorders
* Congenital reproductive conditions
* And other relevant conditions

The condition library is intended to distinguish between **conditions, symptoms, cycle patterns, risk factors, and related health concepts** rather than presenting every menstrual experience as a disease.

---

### Product Science

A developing section focused on menstrual product science and consumer health literacy.

Topics may include:

* Menstrual product ingredients
* PFAS
* Microplastics
* Chemical safety
* Ingredient transparency
* Product labeling
* Regulatory standards
* Environmental considerations
* Current scientific evidence
* Areas where evidence remains uncertain

Sources and evidence will be clearly identified so users can distinguish established findings from emerging research.

---

### Educational Chatbot

A future source-grounded chatbot designed to help users navigate the information available throughout LunaCycle.

The chatbot is intended to:

* Retrieve information from a reviewed knowledge base
* Explain medical concepts in accessible language
* Link users to credible sources
* Clearly distinguish established information from uncertainty
* Avoid presenting itself as a doctor
* Avoid diagnosing or prescribing treatment
* Provide appropriate emergency guidance when a conversation indicates a potentially urgent situation

The chatbot should not automatically access a user's personal health or period-tracking information without explicit user control and consent.

## Evidence & Sources

LunaCycle aims to prioritize reliable, transparent, and accessible health information.

Sources may include:

* Government health agencies
* Peer-reviewed scientific literature
* Medical organizations
* Clinical guidelines
* Academic institutions
* High-quality research databases

Where possible, pages should include:

* Source title
* Author or organization
* Publication date
* Date last reviewed
* Direct source link
* Relevant evidence or research context

The project also aims to communicate uncertainty honestly. Emerging research, conflicting findings, and areas with limited evidence should not be presented as established medical facts.

---

## Accessibility

LunaCycle is designed around the idea that health information should be understandable without requiring advanced medical knowledge.

Planned accessibility features include:

* Plain-language explanations
* Definitions for medical terminology
* Search and filtering
* Responsive design
* Accessible color contrast
* Keyboard-friendly navigation
* Screen-reader considerations
* Multiple language support
* Clear visual organization

Medical terminology may still be included when useful, but it should be explained rather than assumed.

---

## Privacy & Data

Privacy is an important part of the project's future development because menstrual and health information can be highly personal.

The current development phase prioritizes educational functionality before implementing user accounts or long-term personal data storage.

Future privacy features may include:

* User-controlled accounts
* Secure authentication
* Per-user data access
* Ability to edit and delete information
* Ability to export personal information
* Clear data-storage explanations
* Minimal collection of personal information
* Transparent privacy practices

No account or personal health-data system should be considered complete until its security and data-handling practices have been appropriately evaluated.

## Development

LunaCycle is currently developed using **Base44** with GitHub integration.

### Prerequisites

1. Clone the repository using the project's Git URL.
2. Navigate to the project directory.
3. Install dependencies:

```bash
npm install
```

4. Install the Base44 CLI:

```bash
npm install -g base44@latest
```

5. Install [Deno](https://docs.deno.com/runtime/getting_started/installation/) for the local Base44 backend.

Run:

```bash
base44 --help
```

for the available CLI commands.

### Run Locally

From the project root:

```bash
base44 login
base44 link
base44 dev
```

Open the frontend URL provided by `base44 dev` (typically `http://localhost:5173`).

### Important Base44 Notes

Every fresh clone requires:

```bash
base44 link
```

The command creates `base44/.app.jsonc`, which is intentionally gitignored.

`base44 dev` runs the frontend and local backend together. Do not run `npm run dev` separately when using `base44 dev`, because doing so can result in a frontend without the Base44 backend proxy.

The application must have been published at least once before the UI can load correctly under local development.

During local development, entities, functions, and authentication run locally. Entity data is stored in memory and is lost when the local backend restarts.

For frontend development against the hosted backend:

```bash
base44 dev --remote
```

**Use caution:** this mode can interact with production data.

## Publishing

Changes pushed to GitHub are synchronized with the Base44 project.

After making changes:

1. Commit and push the changes to GitHub.
2. Open the Base44 dashboard.
3. Review the changes.
4. Publish the application through Base44.

```bash
base44 dashboard open
```

The GitHub/Base44 workflow should be used rather than deploying an unrelated local tree directly, so the repository and published application remain synchronized.
